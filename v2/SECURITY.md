# Аудит безопасности Miniage v2

Дата: 2026-11-27. Проверялась вся PHP-версия (`v2/src`, `v2/public`).
Методика: чтение кода + активные атаки на запущенный инстанс (curl).

|---|---|---|---|

| 2 | Обход блокировки зон: бой с монстром любого уровня | Высокая | исправлено |

## Что было найдено и исправлено

### 1. Path traversal — критическая

`Router::dispatch()` отдавал файл по пути, склеенному из URL без проверки:

```php
$file = dirname(__DIR__, 2) . '/public' . $path;   // $path = $_SERVER['REQUEST_URI']
if (is_file($file)) { return self::serveFile($file); }
```

Запрос `GET /../src/Core/Config.php` возвращал `200` и **полный исходный код**.
Так же читались `db/schema.mysql.sql`, `preview/package.json` и любой файл,
до которого хватало `../`. При наличии `.env` (реальные доступы к MySQL) —
это прямая утечка учётных данных.

Исправление (`Router::resolveStatic()`): `rawurldecode` → отказ при `..` и NUL →
`realpath` → проверка, что путь лежит **внутри** `public/` → белый список
расширений (`css, js, png, jpg, jpeg, gif, svg, ico, woff2, webp`).

Проверено: `/../src/Core/Config.php`, `/../db/schema.mysql.sql`,
`/%2e%2e/...`, `/..%2f...` → все `404`; `/assets/*` → `200`.

### 2. Обход блокировки зон — высокая

`/api/zones/{zone}` проверял `min_level`, а `/api/battle/start` — **нет**.
С 1 уровня можно было начать бой с Дрейком (20 ур.) простым `mob_id: 10`.

Исправление: в `GameService::startBattle()` уровень персонажа сверяется с
`ZONES[$mob['zone']]['min_level']`.

Проверено: `mob_id=10` → «Зона откроется на 18 уровне», `mob_id=1` → бой идёт.

### 3. Подбор пароля — высокая

12 запросов `/api/login` подряд обрабатывались без ограничений.
CSRF не защищает: токен выдаётся анонимному гостю через `/api/bootstrap`,
так что скрипт получает его за один запрос.

Исправление: таблица `login_attempts` + `AuthService`:
5 неудач в течение 5 минут → блокировка на 10 минут (счётчик по нормализованному
логину). Успешный вход сбрасывает счётчик. Ответ на неверный пароль для
существующего и несуществующего логина одинаковый (нет перечисления аккаунтов).

Проверено: 5 попыток → «Неверный логин или пароль», 6-я → «Повторите через 10 мин».

### 4. Пароли по умолчанию — высокая

Сид создавал `admin/admin` с ролью `admin`. Если `SEED_DEMO` не выключен
на проде — это готовый вход администратора.

Исправление: `SEED_DEMO_PASS` (по умолчанию `demo`) и `SEED_ADMIN_PASS`.
Пустой `SEED_ADMIN_PASS` → генерируется случайный пароль (печатается в лог
только при `APP_ENV != production`). В `.env.example` добавлено
предупреждение «ОБЯЗАТЕЛЬНО смените».

Плюс политика паролей на регистрации: минимум 8 символов, отказ на
`pass*`, `1234567*`, `qwerty*`, `admin*`, `demo*`, `1111*`.

### 5. Заголовки безопасности — средняя

Добавлены на все ответы (включая API) в `public/index.php`:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; connect-src 'self';
                         frame-ancestors 'self'; base-uri 'none'; form-action 'self';
                         object-src 'none'
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: same-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
Strict-Transport-Security: (только при HTTPS)
```

`X-Frame-Options: SAMEORIGIN` не мешает превью: оно грузится с того же origin
через прокси и не является cross-origin iframe.

### 6. Отражение пути в 404 — средняя

`Response::error('Маршрут не найден: ' . $path)` возвращал атакующему его же
URL в JSON. Сейчас сообщение статическое.

### 7. XSS в чате и слабый esc() — средняя

Сервер сохранял текст после `strip_tags()`, но схема вроде `<img src=x
onerror=...>` частично проходила (`strip_tags` вырезает тег целиком, но
конструкции с разорванными скобками могли выжить). Клиент вставляет чат
через `innerHTML`, полагаясь только на `esc()`.

Две линии защиты:
- сервер: `strip_tags` + удаление управляющих символов + удаление `<` и `>`;
- клиент: `esc()` дополнительно экранирует `` ` ``, `=`, `/`.

Проверено: `"text3 <img src=x onerror=alert(1)>"` → сохранилось `"text3"`.

### 8. Спам боями — низкая

Любой мог создать сколько угодно строк в `battles`. Добавлен лимит: не более
3 активных боёв на персонажа.

### 9. `/api/health` — низкая, принято

Отдаёт `PHP_VERSION`, драйвер БД, флаг `wasm`. Полезно для мониторинга, риск
низкий. Если нужна скрытность — закрыть маршрут на уровне nginx.

## Что проверено и оказалось в порядке

| Проверка | Результат |
|---|---|
| SQL-инъекции (zone, kind, shop code, все id) | нет — только prepared statements |
| IDOR: чужой персонаж (`/api/characters/2/select`) | `403`, проверка `account_id` |
| IDOR: чужой инвентарь, чужой бой | `404`, все запросы с `char_id = ?` |
| CSRF: POST без токена / с подделкой | `419` |
| XSS в чате | вырезается |
| Path traversal (после фикса) | `404` |
| Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS | OK |
| Пароли: `password_hash` (bcrypt/argon2), не MD5 | OK |
| Перечисление логинов (текст + тайминг) | одинаковый ответ |
| Отрицательные/огромные `qty` (buy/sell) | клампятся в `1..99` / `1..qty` |
| Огромные координаты `move` | клампятся в `0..900` / `0..560` |
| Смена sid при входе (session fixation) | `regenerate()` |
| `eval`, `include` по пользовательскому вводу | отсутствуют |
| Вывод ошибок в проде (`display_errors`) | выключен, в лог |

## Остаточные риски

1. **`SEED_DEMO=1` в проде.** Демо-аккаунт с известным паролем `demo`.
   Начиная с раздела 15 BUGS.md он создаётся с ролью `player` (раньше был
   `admin`), но вход под ним всё равно открыт — перед публикацией:
   `SEED_DEMO=0` и удалить `demo` из БД. Аккаунт `admin` создаётся отдельно
   и получает случайный пароль, если `SEED_ADMIN_PASS` пуст.
2. **`?s=` в URL.** Fallback для iframe, где cookie недоступны: sid попадает
   в `Referer` и в логи сервера. `Referrer-Policy: same-origin` это смягчает.
   В проде при доступных cookie fallback не активируется.
   Долгосрочно: привязать sid к IP/User-Agent либо заменить на одноразовый токен.
3. **Нет HTTPS в примерах.** `Secure`-cookie и HSTS включаются автоматически
   при `HTTPS`/`X-Forwarded-Proto: https` — за TLS-терминатором всё корректно.
4. **`/api/health`** раскрывает версию PHP. При необходимости закрыть в nginx.
5. **Брутфорс распределённый.** Лимит считается по логину, не по IP: медленный
   перебор с многих адресов по одному паролю в 10 минут всё ещё возможен.
   Для публичного сервера стоит добавить fail2ban или лимит по IP на nginx.

## Как перепроверить

```bash
# обход каталога должен давать 404
curl -s -o /dev/null -w '%{http_code}\n' --path-as-is 'http://localhost:3000/../src/Core/Config.php'

# заголовки
curl -s -D - -o /dev/null http://localhost:3000/ | grep -i content-security

# брутфорс: 6-я попытка должна вернуть блокировку
for i in $(seq 1 6); do
  curl -s -X POST http://localhost:3000/api/login -H 'Content-Type: application/json' \
       -d '{"nick":"demo","pass":"bad"}' | head -c 120; echo
done
```
