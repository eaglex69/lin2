# Перевод игры на PHP 8

Игра («Miniage» / l2war.mobi) написана под PHP 5.3 и старый `php.ini`. После порта код запускается на любом
PHP **8.0 - 8.5** (проверено `php -l` по всем `*.php` и дымовым прогоном каждой страницы на 8.0, 8.3 и 8.5).

> **Важно.** Настоящей базы MySQL в среде, где делался порт, не было: игра ни разу не запускалась с живой БД
> и живыми игроками. Проверялось, что код выполняется на PHP 8 без фатальных ошибок (см. «Как проверялось»).
> Перед выкладкой на боевой сервер нужен прогон на копии базы.

## 1. Что требуется на сервере

* PHP 8.0 или новее (php-fpm / mod_php / CGI);
* расширения: **mysqli** (обязательно), mbstring, iconv, gd (captcha), zlib, ctype, xml (только `bonus/votes_bot.php`), curl;
* MySQL 5.5 - 8.x (схема - `shema.sql`, MyISAM, utf8).

Расширения `mysql` в PHP 7+ нет, поэтому все вызовы `mysql_*()` (их около 4600) работают через слой совместимости на mysqli.
Без расширения mysqli страницы не запустятся: слой пишет причину в `error_log` и выводит одну строку вместо вёрстки.

## 2. Настройка

1. Возьмите `php.ini` из корня как образец (старый - `php.ini.legacy` - для PHP 5.3 и под PHP 8 непригоден:
   `register_globals`, `session.save_handler = inc`, загрузчики ionCube / Zend Guard / eAccelerator / suhosin...).
   Главное в новом:
   * `session.save_handler = files` (значение `inc` в PHP 8 не существует - сессии не заработают);
   * `display_errors = Off`, `log_errors = On`;
   * `date.timezone = Europe/Moscow`;
   * `allow_url_include = Off`.
2. Параметры подключения к БД можно задать переменными окружения (SetEnv в Apache, `env[...]` в php-fpm).
   Если переменной нет - используются значения из `inc/db.php`:

   | переменная | назначение |
   |---|---|
   | `LIN2_DB_HOST`, `LIN2_DB_USER`, `LIN2_DB_PASS`, `LIN2_DB_NAME` | подключение к MySQL |
   | `LIN2_DEBUG=1` | отладка: `error_reporting = E_ALL`, исключения PHP 8 показываются как есть |

3. `sql_mode`. Схема и все `INSERT` писались под MySQL 5.5 с пустым `sql_mode`, а MySQL 5.7/8 по умолчанию «строгие».
   Поэтому после подключения `inc/db.php` выполняет `SET SESSION sql_mode=''`.
   Слова, зарезервированные в MySQL 8.0 (`rank`, `groups`, `system`, `row`, `lead`...), в схеме не встречаются; старые
   (`char`, `drop`, `from`, `interval`, `kill`, `on`, `out`, `read`) в запросах уже стоят в обратных кавычках.

## 3. Что изменено

### Слой совместимости (новые файлы)

* `inc/php8.php` - подключается первой строкой `inc/db.php`:
  * `error_reporting`. Старый `php.ini` работал с `error_reporting = 1` (только фатальные ошибки), поэтому в страницы никогда
    не попадали «Undefined variable/index». В PHP 8 это предупреждения, а вывод до `header()` / `setcookie()` ломает редиректы.
    Пока не включён `LIN2_DEBUG`, уровень ограничен фатальными ошибками;
  * часовой пояс `Europe/Moscow`, если он не задан в `php.ini`;
  * обработчик необработанных исключений (`TypeError`, `ValueError`, ...): пишет в `error_log` и показывает игроку короткое
    сообщение вместо стека с путями файлов;
  * вспомогательные функции `lin2_div()` (деление без `DivisionByZeroError`, как в PHP 5), `lin2_readdir()` и
    `lin2_closedir()` (каталог не открылся - в PHP 5 было предупреждение, в PHP 8 `TypeError`).
* `inc/mysql_compat.php` + `inc/mysql_compat_impl.php` - функции `mysql_*()` поверх mysqli (39 функций, в том числе
  `mysql_result`, `mysql_fetch_*`, `mysql_num_rows`, `mysql_insert_id`, `mysql_real_escape_string`, константы `MYSQL_*`).
  Если расширение `mysql` всё-таки есть, слой ничего не делает. Нужен PHP >= 8.0.

### Синтаксис и удалённые возможности

* короткие теги `<?` -> `<?php` (184 файла; в PHP 8 `short_open_tag` по умолчанию выключен);
* «голые» строки в ключах массивов и константах (`$row[name]` -> `$row['name']`, ~5800 мест в 196 файлах: PHP 8 бросает
  `Error: Undefined constant`);
* конструкторы PHP 4 (`function KCAPTCHA()`) -> `__construct`, обращение к символу строки `$s{0}` -> `$s[0]`;
* семейство `ereg*` (удалено в PHP 7) -> `preg_*` в `msg.php`, `tchat.php`, `clanroom.php`, `gifts.php`, `account.php`,
  `reg.php`, `reg_site.php`;
* `strftime()` в `date.php` (устарела в 8.1) -> `date()`;
* `case X;` -> `case X:` (точка с запятой после метки `switch` объявлена устаревшей в PHP 8.5; 52 метки в 18 файлах), `xml_parser_free()`
  в `bonus/votes_bot.php` вызывается только до PHP 8.0 (в 8.5 функция устарела);
* синтаксические ошибки в неиспользуемых файлах (`inc/opitost.php`, `log.php`, `sab.php`);
* `inc/AntiHack.class.php`: `null` в `preg_replace()` / `str_replace()`, массивы в чистильщике, `{}`-смещения,
  `is_uploaded_file()`; `mb_detect_encoding()` с PHP 8.3 называет текст не в UTF-8 (например, форму в cp1251) «ASCII», а раньше
  отвечал «UTF-8» или `false` - проверка сделана явной, чтобы результат не зависел от версии PHP (такой текст
  перекодируется из `WINDOWS-1251`, как и задумано в коде; для обычных UTF-8 запросов ничего не меняется);
* `inc/mysql.php`: `mysql_insert_id()` без ссылки на соединение, проверка элементов `debug_backtrace()`.

### register_globals

Игра работала с `register_globals = On`: часть переменных создавалась из `$_GET` / `$_POST` / `$_SESSION` / `$_SERVER`
без единого присваивания в коде. Там, где это влияло на поведение, чтение сделано явным (`password.php`, `inc/auth.php`,
`shop.php`, `shop_gold.php`, `shop_lux.php`, `shop_vip.php`, `shop_chat.php`, `clan_shop.php`, `tiket.php`, `msg.php`,
`index.php`, `index_site.php`, `inc/foot_inf.php`, `inventar.php`). Около 35 переменных читаются, но нигде не задаются
(`$inpk`, `$inar`, `$kol`, `$sd` ...) - они и раньше были пустыми, поведение прежнее.

### Прочее поведение PHP 8

* деление на ноль (`/`, `%`) - `DivisionByZeroError`: полоски HP/MP (`inc/zag.php`, `battle.php`) и опыта
  (`inc/opit.php`, `inc/opits.php`) считаются через `lin2_div()`;
* каталоги с картинками (`pic/smiles`, `pic/clan`, `pic/clan_logo`, `foto`) в репозитории отсутствуют - они лежат только на
  сервере. Если каталога нет, `opendir()` возвращает `false` и цикл `lin2_readdir()` просто не выполняется, а список файлов остаётся
  неопределённым: `sort(null)` / `count(null)` в PHP 8 - `TypeError` (в PHP 5 - тихий ноль). В `chat.php`, `msg.php`, `smile.php`,
  `home.php` и `gm/ava.php` список перед этим становится пустым массивом;
* `gallery.php`: `fread($fp, 0)` для пустого загруженного файла в PHP 8 - `ValueError` (раньше предупреждение, и запись в галерею
  всё равно создавалась); чтение (результат нигде не используется) теперь пропускается для пустого файла;
* `checkin::display_pagin()` вызывается статически - объявлена `static`, четвёртый параметр необязателен;
* `inc/endmain.php`: `info_compress()` лежит в отсутствующем `inc/gzips.php` - вызов защищён `function_exists()`;
* `inc/db.php`: `session_start()` только если сессия ещё не запущена (`enter.php`, `avt.php` запускают её сами), для входов без
  `inc/path.php` задаётся `$path = ''`;
* `KCAPTCHA::$keystring` объявлено свойством (динамические свойства устарели в 8.2);
* нечисловое значение (`?page=abc`, пустое или с буквами поле суммы) в PHP 5 было просто нулём, в PHP 8 оно ведёт себя иначе:
  * `'abc' + 1`, `round('')` бросают `TypeError`. Постраничная навигация (`$_GET['page']`, 26 мест в 20 файлах) теперь
    сбрасывает нечисловое значение в 0, `$_GET['start']` и `$_GET['logs']` приводятся к `int` (`smile.php`, `clanroom.php`,
    `home.php`, `gm/ava.php`); `round()` / `floor()` над полем формы (`anti_pk.php`, `kill_ob.php`, `obm_fs_ad.php`,
    `wmr_obmen.php`) получают `(float)`;
  * проверки «сумма больше нуля» вида `if ($_POST['gold'] <= 0 or ...)` в PHP 5 отсекали мусор (`'abc' <= 0` было `true`), а в PHP 8
    `'abc' <= 0` - `false`, и мусор шёл бы дальше (до `TypeError` в расчёте или прямо в базу). В 39 таких сравнениях
    (19 файлов: `bank.php`, `bazar.php`, `bazar_col.php`, `bazar_vip.php`, `bazar_wmr.php`, `pitomec.php`, `clanroom.php`,
    `shopsoul.php`, `shopelexirs.php`, `webmoney.php`, `wmr_obmen.php`, `kill_ob.php`, `obm_fs_ad.php`, `col_bonus.php`...)
    значение приведено к числу: `(float)$_POST['gold'] <= 0` - это ровно то, что делал PHP 5;
  * в остальных местах мусорный параметр даёт `TypeError` - его перехватывает обработчик из `inc/php8.php`: игрок видит короткое
    сообщение, подробности пишутся в `error_log` (так, например, ведут себя панели `adm_panel.php` / `mod_panel.php` /
    `gm/wm.php` при пустой сумме или сроке бана: в просмотренных местах расчёт стоит раньше записи в базу);
* `avt.php`, `battle.php`, `combat.php`, `enter.php`, `fight.php`, `pk.php` выполняют код (чтение `$_GET`, `session_start()`)
  до подключения `inc/db.php`, поэтому `inc/php8.php` подключается в них самой первой строкой (иначе предупреждения PHP 8
  успевали бы попасть в страницу раньше `session_start()` и `header()` на серверах с `display_errors = On`).

## 4. Что осталось как есть (не связано с PHP 8) - стоит знать

* **Пароль БД и имена схем зашиты в код**: `inc/db.php` (переопределяется переменными `LIN2_DB_*`) и `log.php`
  (устаревший отдельный вход, нигде не подключается). Рекомендуется сменить пароль и убрать его из репозитория.
  Имена баз в SQL: `db1464828399` (`inventar.php`), `l2warmobi` (`adm_panel.php`).
* Нет в репозитории (только предупреждения, скрытые `error_reporting`; функции, видимо, существовали на старом хостинге):
  `inc/avtoopt.php`, `inc/interval.php`, `inc/regfunc.php`, `inc/gzips.php`, `inc/antiddos.php`, `inc/smsbill.class.php`,
  `inc/settings_sms.php`, каталоги с пользовательскими картинками `pic/`, `foto/`.
* В репозитории нет определений функций `subtok()` (`inc/core.php`), `num()` (`forum/index.php`), `msg()` и `str()`
  (`gifts.php`), `domin()` (`index_site.php`), `ryd()` (`to_zamok.php`) и классов `SMSBill` (`coin_sms.php`), `InitVars`
  (`inc/ini.php`) - вероятно, они лежат в тех самых отсутствующих файлах. Заглушки я не добавлял, чтобы не получить
  «Cannot redeclare» рядом с настоящими определениями; без них эти ветки падают так же, как падали на PHP 5.
* `inc/foot_text.php` при подключении из функции (`lose()` в `combat.php`) обращается к `$mysql`, которого нет в локальной
  области - фатальная ошибка и на PHP 5, только у игроков с текстовым подвалом.
* Мёртвые / служебные файлы: `gk.php`, `uslugi_exp.php`, `teleport.php`, `delete_usr.php` (вызовы `mysql_querry`), `coin_sms.php`,
  `sab.php`, `log.php`, `pnews.php`, `chat2.php` и `forum/down.php` (фрагменты), `inc/ini.php`. Приведены к синтаксису PHP 8 там,
  где это было нужно, но не проверялись по смыслу. `php.php` и `gzip_pr.php` - `phpinfo()`, лучше удалить с боевого сервера.
* В таблицах схемы `shema.sql` нет таблиц, к которым обращается код (`job_pvp`, `ru`, `user`, `domination`, `world`, `arena_log`,
  `pk_log`, `shop_aura`, `getekeeper`) - дамп старее кода.
* `reg.php` и `reg_site.php`: проверка e-mail через трёхаргументный `ereg()` и раньше не выполнялась (мёртвая ветка), теперь это явное
  `elseif (false ...)`. Поведение прежнее: адрес не проверяется.
* `account.php`, `reg.php`, `reg_site.php`: проверки допустимых символов вида `@preg_replace("[A-za-z0-9]+", "", $_POST['pass'])`
  написаны без разделителей (`[` сам становится разделителем, `+` - неизвестным модификатором), результат всегда `NULL`, и проверка
  никогда не срабатывала - на PHP 5.2, 7.4, 8.3 и 8.5 одинаково (проверено). Работает только соседняя `preg_match('/[^a-z0-9-]/i', ...)`
  для ника. Поведение не менялось.
* Сравнения числа с нечисловой строкой в PHP 8 дают другой результат (`0 == 'abc'` раньше было `true`, теперь `false`).
  Проверено: элементы массива (строки БД) против целого `0` - 94 места, ни одно не относится к текстовому столбцу, где лежит слово;
  значения `$_GET` / `$_POST` против числового литерала (`<`, `<=`, `>`, `>=`, `== 0`) - исправлено (см. выше). Остальные
  сравнения (в том числе переменные, в которые значение попало окольным путём, и `switch` по числам) целиком не аудировались -
  если в игре заметите странность в условиях, смотрите сюда в первую очередь.

## 5. Как проверялось

Инструменты лежат в `tools/php8` (их можно не выкладывать на сервер; см. `tools/php8/README.md`):

* `lint.mjs` - `php -l` по всем 233 файлам на PHP 8.0, 8.3 и 8.5: 0 ошибок и предупреждений;
* статические проверки: короткие теги, `ereg`, `{}`, деление, число аргументов, динамические свойства, `register_globals`,
  сравнения и арифметика над значениями `$_GET` / `$_POST`, `case X;`, код до `inc/db.php`;
* **дымовой тест**: `smoke/run.mjs` запускает каждую страницу (190 входных файлов) на PHP 8 (WebAssembly) против поддельного
  MySQL-сервера, построенного по `shema.sql`, как гость и как игрок, с параметрами и ветками `switch` из исходника, с профилями
  данных (обычные / нули / пустая БД) и «мусорными» параметрами (`abc`, пустые значения).
  Итог финальных прогонов (PHP 8.3 - как на боевом сервере и в режиме `LIN2_DEBUG`, в том числе с «мусорными» параметрами и без
  каталогов `pic/`, `foto/`; PHP 8.0 - как на боевом сервере; PHP 8.5 - в режиме отладки): остаются только шесть падений в коде из
  раздела 4: три файла без собственного подключения к БД (`chat2.php`, `pnews.php`, `forum/head.php` - фрагменты и мёртвые
  страницы, напрямую не запускаются; тест открывает их по одному) и три места, которые падали и на PHP 5 (нет класса `SMSBill`
  в `coin_sms.php`, нет функции `domin()` в `index_site.php`, `$mysql` вне области видимости в `inc/foot_text.php`); других
  исключений нет. Предупреждения и устаревшие вызовы (в основном «Passing null
  to parameter», «Undefined variable / array key») видны только в режиме `LIN2_DEBUG`: как и на PHP 5, при обычной настройке
  они скрыты, на работу не влияют;
* `smoke/bots.mjs`: оба cron-робота из `bonus/` (`votes_bot.php`, `bonus_bot.php`) проходят до конца на PHP 8.0 / 8.3 / 8.5:
  соединение, создание таблиц, запросы и закрытие идут через слой `mysql_*`. Это проверка вызовов, а не работы бота: поддельная БД
  отдаёт две строки на любой `SELECT`, запрос к vigre.su не выполнялся.

Что **не** проверено: работа с настоящими данными (поддельная БД не хранит состояние, поэтому смысл игровых расчётов - бои, магазины,
банк, кланы - не сверялся с PHP 5), производительность и поведение под нагрузкой. Перед боевой выкладкой нужен прогон на копии базы.
